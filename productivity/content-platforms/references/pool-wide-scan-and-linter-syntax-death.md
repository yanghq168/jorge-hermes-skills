# 缺陷二十：从「只查当晚」升级到「全池回扫」+ 审计工具的 SyntaxError 死法

**2026-11-17 头条号实测。** 当晚 `audit_rendered_article.py` **exit 0**、
`lint_content_consistency.py` **exit 0**、假阳性检查 **exit 0**、
跨夜碰撞 **exit 0**、脚本 exit 0、飞书 `message.get` 回查送达 ——
**全程绿灯**，人工通读 + 全池扫描仍抓到 **11 处读者可见硬伤**。

本文档讲两件事：

1. **把 8 字复读扫描从「当晚一篇」升级到「全池 20 条」** —— 一次修 9 个方向，
   覆盖未来 10 个夜晚，而不是等每个方向各自轮到时再被抓一次。
2. **审计工具的第三种死法：`SyntaxError`（不是 `NameError`）** ——
   **症状与「内容有问题」完全相反**，照惯例「看到 exit 1 就去改文案」会把对的改坏。

## 一、全池回扫：为什么必须扫全池而不是只扫当晚

当晚的 8 字复读扫描（见 `references/field-echo-and-sum-vs-total-audit.md`）
最初只跑了当夜的「亲戚恩怨」方向，发现 1 处。**顺手把同一段扫描代码套到
全池 20 条上（10 长文 + 10 微头条），一次跑出 21 处** —— 分布在 9 个方向。

| 方向 | 命中数 | 典型 |
|---|---|---|
| 遗产分配 | 4 | `title`↔`story_a_ending`「三个子女差点打起来」9字 |
| 房产纠纷 | 4 | `title`↔`story_a_dialogue`「说这房子是我们的你凭什么住」13字 |
| 赡养义务 | 3 | `hook`↔`story_a`「搜老人养老院一个月多少钱她假装没看见」18字 |
| 随礼人情 | 3 | `hook`↔`story_a`「当年他随过份子钱的邻居」11字 |
| 再婚财产 | 2 | `hook`↔`ext_a`「我不是要跟孩子们争房子…」**25字** |
| 亲戚恩怨 / 晚年孤独 / 养老院 / 兄弟姐妹 / 远居赡养 | 各 1 | — |

**这个分布本身就是发现**：每个方向单独看只有 1 处（不到「值得单独修」的阈值），
**合起来 21 处**才是真实规模。**只看当晚 ⇒ 每晚只修 1 处，要修 10 个晚上；
一次全池 ⇒ 一个晚上修 11 处。**

### 成本极低 —— 复用同一段代码，只是外层多套一层循环

```python
for t in pool.TOPICS_POOL:        # ← 唯一的改动
    ext = E.get(t['direction'])
    F = dict(t); F['ext_a'] = ext[0]; F['ext_b'] = ext[1]
    ...  # 与当晚扫描完全相同的代码
```

### 修法顺序（重要）

- **修「当晚方向」优先**（读者手上那份已受影响），**再修其余方向**（未来夜晚）。
- 修完立刻**再跑一次全池扫描**确认命中数下降（当晚 21 → 14）。
- 剩下的命中**逐条人工核对**，其中一部分是**设计约束而非缺陷**：
  钩子必须兑现自己的引语/标题承诺（`HOOK_PROMISE` 规则要求），
  所以「hook↔正文」出现同一句**有时是必须的** —— 这类**不要改**，
  改成「正文换个说法但保留同一承诺」。

## 二、🔴🔴 审计工具的第三种死法：`SyntaxError`（工具被 XML 片段污染）

### 现象

`content-platforms/scripts/verify_cross_night_collisions.py`
**文件尾部多出一行 `</content>`**（疑似某次 XML 片段误粘进源码）：

```
$ python3 verify_cross_night_collisions.py --pool ... --nights 60 --json
  File ".../verify_cross_night_collisions.py", line 266
    </content>
    ^
SyntaxError: invalid syntax
```

### 为什么这次特别危险

`lint_content_consistency.py` 的退出码语义是：

| 退出码 | 含义 | 应对 |
|---|---|---|
| 0 | 内容干净 | — |
| **1** | **内容有问题** | **去改文案** |
| **2** | 工具自检失败（工具坏了） | 去修工具 |

**`SyntaxError` 让 Python 直接以 exit 1 退出** —— **与「内容有问题」完全同码**。
当晚若按惯例「exit 1 ⇒ 改文案」，会把**本来正确的文案改坏**。

### ✅ 硬规则：判别「工具死了」vs「内容有问题」看 stderr 的形状

| stderr 形状 | 判定 | 应对 |
|---|---|---|
| 有 traceback，且最后一行是 `SyntaxError` | **工具文件本身坏了** | 修工具，别碰文案 |
| 有 traceback，是 `NameError: xxx 未定义` | 工具内部坏了 | 修工具 |
| 无 traceback，有规则名 + 命中项 | 内容有问题 | 改文案 |
| stdout 空 + stderr 有 traceback | **工具崩了**（不是内容） | 修工具 |

**判别口诀（扩展版）：先看 stderr 有没有 traceback，再决定动谁。**
不要只看退出码 —— 退出码 1 有两种完全相反的含义。

### 当晚的修法

```bash
tail -c 300 verify_cross_night_collisions.py | od -c | tail -20   # 定位多余行
# 删掉尾部那行 → py_compile 通过 → 重跑 exit 0 → 跨夜碰撞 0/60
```

### 🔴 附带教训：自 11-15 落地后**无人调用**的工具会静默腐烂

`verify_cross_night_collisions.py` 是 2026-11-15 才落地的，
**当晚是第一次真正跑它** —— 一跑就是 SyntaxError。
**新工具落地 ≠ 工具可用**；**「写完了」必须至少真跑一次**，
否则它会在产线上烂几个月，直到某天有人碰巧调用。

**建议（已固化到本技能的纪律）**：任何**新落地的校验器**，
在同一次会话里必须用**真实生产参数**跑一遍并记录退出码，
否则不许写进报告的「工具链状态」那一行。

## 三、当晚抓到的 11 处硬伤（按缺陷族归类）

### 族 1：钩子整句复读（缺陷十四）—— 5 处

钩子的句子在正文里**逐字复读**。逐句归一化后 `in` 检测：

| 方向 | 复读内容 |
|---|---|
| 赡养义务 | hook「她假装没看见」↔ story_a 整句 |
| 房产纠纷 | hook「工作人员问了他三遍」↔ story_a 整句 |
| 随礼人情 | hook「当年他随过份子钱的邻居」↔ story_a 整句 |
| 养老院 | hook「三个子女都孝顺，可她心里空落落的」↔ story_a 整句 |
| 远居赡养 | hook 引语「孩子的心是真的，可手不在你身边」↔ story_a_ending 整句 |

**修法：改正文那一句，不动钩子。**（钩子是流量钩子，优先级高于正文顺滑。）

### 族 2：钩子与结局自相矛盾（**全新，本次最严重**）

亲戚恩怨：
- **hook 说**：「那是他最后一次收到侄子的消息」
- **结局里**：小强回了条短信「行。」，还把微信屏蔽了

**钩子宣称「再也没有消息」，结局里却有一条后续消息** —— 读者读到结局会愣住：
到底还有没有消息？

**修法**：把 hook 的绝对化表述改成「从那以后，李大爷的手机再没响过」
（既保住流量钩子的力度，又不与结局矛盾）。
**注意：改 hook 是例外**，仅当 hook 本身与正文冲突时；
其余复读一律「改正文，不动钩子」。

### 族 3：金额链糊账（头条读者一按计算器就穿帮）

- 亲戚恩怨：「3万 + 5万 + **十来万** = 差不多20万」—— 「十来万」是糊账
  ⇒ 改成「又给了小强**12万**，加起来**正好**20万」
- 再婚财产：ext_b「一天50，一个月1500」与 story_b 复读

### 族 4：时长链算不通

- 亲戚恩怨：高中3年 + 大学4年 + 毕业半年 ⇒ **七八年**，原文写「五六年」
- 需同时改 `story_a_ending` 与 `ext_a` 两处（**同一件事两个时点**）

### 族 5：孙辈/子女称谓链断裂（全新）

隔代育儿（微头条）：
- **孙子叫老周「爸」** —— 老周是爷爷 ⇒ 改「爷爷」
- **儿子把「儿媳」称作「妈」** —— 那是儿子自己的妈，
  但规矩是**儿媳**给的 ⇒ 改「孩子妈」
- **标题「第二条我做不到」与正文对不上** ——
  规则二写「零食」，正文违反的却是规则三「冷饮」
  ⇒ 改正文：违规点改成买**零食**两次（规则二），冷饮不再碰

⚠️ **称谓链扫描配方**（可直接复用）：

```python
# 孙辈叫爷爷/外公「爸/妈」—— 按角色层级反查
for mm in re.finditer(r'(孙子|孙女|外孙)[^。！？\n]{0,12}问：\'爸', txt):
    print("🔴 孙辈称谓错位:", mm.group(0))
# 子女把「儿媳/儿媳妇」称作「妈」—— 说话人视角矛盾
for mm in re.finditer(r'(儿子|女儿)[^。！？\n]{0,6}打电话来：\'爸，妈', txt):
    print("🔴 儿媳被称作妈:", mm.group(0))
```

### 族 6：钩子承诺未兑现

隔代育儿 hook：「老周带孙子带了**三年**」—— 正文从头到尾没交代三年
⇒ **写进正文**（「孙子放暑假就送回老周家，三年了」），**不要把钩子写软**。

## 四、修复纪律（当晚全部遵守）

1. **逐条落盘**：每条替换成功后立即写文件，失败的单独报告、不回滚已成功的。
2. **锚点用最小唯一片段**，匹配数 ≠ 1 就**先打印真实源文本再改**。
   ⚠️ **今晚连踩 3 次「锚点猜错」**：以为在 `toutiao-article-daily.py`，
   实际在 `toutiao_topics_extra.py`（EXTRA_TOPICS）或
   `toutiao_story_extensions.py`。
   **修法：不知道在哪个文件时，先 `for f in 三个文件: txt.count(key)` 定位。**
3. **回读断言**：新串**可以包含旧串作为前缀**（如「在门口等开庭…他跟律师又说了一遍」
   → 同句 + 新增一句），所以断言应写成
   `assert old not in back and new in back`，
   **不要写 `assert new not in back`**（会假失败）。
4. **改完立刻量字数**：当晚隔代育儿从 248 → **256 越界**，
   靠「改一句就量一次 CJK」压回 250（`lint` 不查字数区间，
   只有 `audit_rendered_article.py --pool` 渲染后看得到）。
5. **`py_compile` 三个源文件**。

### 批量替换的「半程落盘」要当心

当晚一次批量跑 11 条，第 3 条锚点失败 → **前 2 条已落盘**。
后续重跑时若不先核对「哪些已改」，会重复改或误判。
**做法：每条落盘后立刻回读断言并计数**，重跑前先
`for key in [...]: print(txt.count(key))` 确认当前状态。

## 六、当晚的教训清单（可直接当 checklist 用）

1. **全池回扫 > 单篇扫描** —— 一次修 9 个方向，而不是每晚修 1 个。
2. **判别「工具死了」看 stderr 的形状，不看退出码** ——
   `SyntaxError` 与「内容有问题」同码（exit 1）。
3. **新落地的校验器必须真跑一次** —— 落地 ≠ 可用。
4. **钩子与结局的矛盾要改 hook**（唯一例外场景）。
5. **其余复读一律改正文，不动钩子。**
6. **改一句就量一次 CJK** —— 微头条 150–250 是硬约束，`lint` 不查。
7. **锚点不确定时先跨三个源文件定位** —— 今晚连踩 3 次文件找错。
8. **回读断言允许新串含旧串前缀。**
