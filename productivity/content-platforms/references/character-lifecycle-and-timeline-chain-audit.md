# 缺陷十一「人物生死状态链断裂」+ 缺陷十二「时间线链打架」

> 2026-11-10 实测。头条长文《65岁老人随了20年份子钱，最后一场酒席没请他：人情薄如纸》
> —— audit exit 0 + lint exit 0 + 脚本 exit 0 + 飞书附件已回查送达，**全程绿灯**，
> 但手工通读抓到 **10 处读者可见硬伤**，其中 2 处属于本文件记录的两类**全新**缺陷。

## 一、缺陷十一：人物生死状态链断裂（已故角色仍在说话）

### 现象

故事A 的设定是**老伴已经去世**（正文明确写「老伴走了三个月」「对着遗像说」），
但 `story_a_dialogue` / `ext_a` 里的**台词仍然让老伴开口说话**。

读者视角：文章刚交代人没了，下一段这人还在跟他对话 —— 直接出戏。
头条中老年读者对「死人复活」极其敏感，比数字算错更刺眼。

### 为什么现有全部规则都测不到

| 规则 | 为什么漏 |
|---|---|
| `PHANTOM_SON` | 查的是「凭空多出的人物」（主体故事里没有这个人）—— 老伴**是**合法角色 |
| `ORPHAN_CHARACTER` | 查的是扩写段落整体换了主角 —— 这里是同一角色跨段落状态矛盾 |
| `HOOK_PROMISE` | 查钩子/标题承诺有没有兑现 —— 跟生死状态无关 |
| `GOLDEN_ECHO` | 查金句复读 —— 跟生死状态无关 |
| `SUM_*` / `SPLIT_*` | 查数值链 —— 跟生死状态无关 |

**根因**：现有规则全是「数值链」和「存在性」两种口径，缺第三种 ——
**状态链**（这个人在故事的这个时间点，还活着吗）。

### 检测口径（人工通读，不是硬规则）

**角色生死/离场状态链**：

1. 先在**主体故事**里找出每个角色的**状态转折点**（去世/离婚/住院/搬走/断绝往来/入狱）。
2. 在**转折点之后**的每个字段里（对话/结局/扩写/观点/行动）搜该角色的名字或代词。
3. 命中即为缺陷 —— 除非那一句明确是「回忆」「对着遗像说」「梦见」这类有交代的写法。

**判定要点**：
- 允许：「他对着遗像说了句」「他想起老伴从前…」「他梦见老伴还在」
- 不允许：「老伴把包递给他」「老伴说：你别去了」—— 无任何状态交代

⚠️ **代词比人名更危险**：扩写段里常常不写名字，只写「她」「老伴」。
人名 grep 抓不到，**必须逐段读**，看主语是谁。

### 修法

**加状态交代，而不是删角色**：

| 写法 | 判定 |
|---|---|
| ❌ `老伴把包递给他` | 死人复活 |
| ✅ `老伴的旧外套还搭在椅背上，他把包搁进去` | 状态一致 |
| ✅ `他对着老伴的遗像说：…` | 状态一致（显式交代） |

修完还要**回扫该角色在所有字段的出现位置** —— 一处改了、另一处还在说话，等于没改。

## 二、缺陷十二：时间线链打架（同一事件两个时间口径）

### 现象（今晚 2 处）

1. **烧本子的时间**：结局写「办完丧事当天烧」，扩写段写「老伴走了3个月才烧」
   → 读者会算：到底办丧事那天烧的，还是三个月后烧的？
2. **同一金额两个值**：主体段写「赵老师随了 1500」，台词却说「这 1000 不算什么」
   → 读者一按计算器：到底 1000 还是 1500？（注：这同时也是金额链问题，
   但**同字段内的台词重复了另一个金额**是独立表现）

### 检测口径

**时间线链**（加进通读清单）：

| 检查项 | 方法 |
|---|---|
| 事件时点唯一 | 同一事件（办丧事/搬家/住院/签约）在不同字段是否只有一个时点 |
| 相对时间 vs 绝对时间 | 「三个月后」和「办完丧事当天」是否指向同一事件 |
| 先后顺序 | 事件 A 是否被写成在 B 之后，实际在 B 之前 |

**修法**：**统一到一处口径，然后改所有其他处**。改完回扫该事件关键词的全池出现。

### ⚠️ 今晚踩到的坑：改一处 ≠ 全池修完（第三次复现）

修「烧本子的时间」时，同时改了 `story_a_ending` 和 `ext_a`，但**扩写里还有第三处**
提到烧本子（叙述角度不同）。**必须按「事件关键词」全池 grep，而不是按「你记得的那几处」改**。

修法：
```bash
grep -n "烧本子\|本子" ~/.hermes/cron/scripts/toutiao_topics_extra.py \
                     ~/.hermes/cron/scripts/toutiao_story_extensions.py
```
按**关键词**回扫，不按**位置**回扫。

## 三、通读清单扩容：8 条链 → 10 条链

原有 8 条（年龄/金额/时长/同属性取值/币种/汇总/薪资/同角色称呼）
见 `content-platforms` SKILL.md 与 `references/orphan-extensions-and-hand-arithmetic-audit.md`。

**新增第 9、10 条**：

| # | 链 | 问什么 |
|---|---|---|
| ⑨ | **角色生死状态链** | 这个人在故事的这个时间点，还活着吗？有没有交代？（死/离/断/住院） |
| ⑩ | **时间线链** | 同一件事有没有两个时点？相对时间（三个月后）和绝对时间（当天）指同一件事吗？ |

⚠️ **⑨⑩ 都是「存在性/数值链」测不到的第三、第四种口径**：
- 数值链：数字算不算得通
- 存在性链：角色存不存在
- **状态链**：角色**该不该**还在场
- **时间链**：事件的时点唯不唯一

## 四、工具用法坑（今晚新增，很重要）

### `lint_content_consistency.py --pool` 必须指向**生成器脚本本身**

```bash
# ✅ 正确：指向生成器脚本
python3 lint_content_consistency.py \
    --pool ~/.hermes/cron/scripts/toutiao-article-daily.py \
    --extensions ~/.hermes/cron/scripts/toutiao_story_extensions.py

# ❌ 错误：指向池数据文件（toutiao_topics_extra.py 或 JSON）
#    → exit 2
```

**exit 2 = 参数用错（装配不出正文），不是内容有问题。**

⚠️ **别据此去改文案**：exit 2 与 exit 1 语义完全相反 ——
- exit 0 = 内容干净
- exit 1 = 内容有问题
- **exit 2 = 工具自检失败 / 参数用错**

今晚差点因为 exit 2 去「修」本来正确的文案。**先看 stderr 确认是哪一种**。

### 修复后的复核要在**隔离 harness** 里跑

改完源码必须用隔离 harness 验证，且**生产 `topic_history.json` 不能被污染**：

1. harness 用临时 history 路径
2. 跑完 `diff` 生产 history → **必须为空**
3. 三个工具都跑，退出码**单独看**（不要用管道吞掉）：
   ```bash
   python3 lint_content_consistency.py --pool ... --extensions ... > /tmp/lo.txt 2>/tmp/le.txt
   echo "REAL EXIT=$?"; cat /tmp/lo.txt; echo "--stderr--"; cat /tmp/le.txt
   ```
4. `py_compile` 三个源文件

### ⚠️ 收尾被工具额度截断的教训

今晚最后一次修复（改掉「烧本子」在 `story_a_ending` 与 `ext_a` 的**重复叙述**）
**源码已写入且 `py_compile` 通过，但最终 harness 复渲染与复核没跑完**。

**规则**：一次会话里如果有**多批**修复，把「第一批」在会话早期就完整验证并落盘；
后面的批次如果要跨会话，**必须在报告里明确写「本批未复渲染验证，明晚首跑后确认」** ——
不要让「改了但没验证」的状态被后续会话当成「已验证」。
