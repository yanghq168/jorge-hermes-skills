# 「批次替换只改掉链的一部分」+「池里有没有重复条目」的判别口诀

**2026-11-26 头条号实测。** 当晚 `audit_rendered_article.py` / `lint_content_consistency.py` /
`verify_cross_night_collisions.py` / `check_pool_type_false_positives.py` /
`scan_pool_defects.py` **exit 全 0**，脚本 exit 0，飞书 `message.get` 回查送达 —— **全程绿灯**。
仍靠人工通读抓到 **1 处真缺陷（读者按计算器就能穿帮）**，且它是一处**跨 5 夜复发**的残留。

## 一、当晚抓到的缺陷：上次修复只落了一半

微头条②（方向 `工龄错算`）：《退休时发现工龄少记了 **3 年**，重新核定后每月多领 **62 元**》

| 位置 | 原文 | 状态 |
|---|---|---|
| 标题 | 工龄少记了 **3 年** | ✅ |
| 正文 | 「1998 年到 2000 年在三产干了 **三年**」 | ✅ |
| 正文 | 考勤表「记着 **整三年**」 | ✅ |
| 正文 | 「最后重新核定了工龄：**少记的 3 年**补上」 | ✅ |
| **对话（窗口答复）** | 「**你档案上只有半年**」 | ❌ **← 残留** |

⇒ 标题说 3 年，窗口却答复「只有半年」⇒ **读者一按计算器就穿帮**。

### 根因：批次替换只改了「链的一部分」

这个条目在 **11-21** 被修过一次（见
`references/scene-consistency-and-actor-role-audit.md` Finding 7：微头条数字链断裂）。
当时改了两处：`干了一年 → 干了三年`、`只记了半年 → 记着整三年`，
**但漏改了同一句里紧邻的「你档案上只有半年」**。

⇒ 11-21 的修复**本身是对的**，只是**不完整**；残留的那一处继续存活，
直到 11-26 这条选题再次被 LRU 抽到（微头条池 10 条 ÷ 2 条/晚 ⇒ 约 5 夜一轮）才暴露。

### 🔴 纪律：要让一条数字链自洽，必须**先列全链再一次性落盘**

```
链上每一处 → 逐处标「改 / 不改」→ 一次性落盘
```

当晚的链（8 处）：
`标题 3年` / `干了三年` / `只有半年`❌ / `记着整三年` / `少记的3年` /
`62元×12=744` / `12年下来` / `744×12=8928`

- **要改**：只有「只有半年」这一处（标题已经对了，链条其余部分已自洽）。
- **不能改**：`62×12=744` 与 `744×12=8928`（算式引用着 `12年`，动了会连带崩）。
- **不是冲突**：`我等这句话等了十六年`（1998→2014）与 `12年下来`（2014→2026）
  —— **测的是两个不同区间**，不需要统一。

> ⚠️ 「先列全链」不等于「把所有数字改成一样」。**先判断每一处是否真的在同一口径上。**

### 修法（当晚实际采用）

```python
# 锚点唯一性断言 → 落盘 → 回读双向断言 → py_compile → 量 CJK
OLD = "窗口的人翻了翻档案，说：'你档案上只有半年。'"
NEW = "窗口的人翻了翻档案，说：'你档案上这三年，一个字都没有。'"
```

- 锚点 `count == 1` 断言 → 落盘 → 回读 `OLD not in back` + `NEW in back` → `py_compile` rc=0
- **修完立刻量 CJK**：242 → **247 字**，仍在微头条硬约束 [150, 250] 内 ✅
- 备份 `toutiao_topics_extra.py.bak_20261126_2053`

⚠️ **「一个字都没有」比「只有半年」更贴题**：它同时解释了「为什么档案上没有这三年」
和「为什么他能翻出考勤表」—— 叙事上也顺。**改数字时优先选「能顺带补上因果」的措辞。**

## 二、⚠️ 假警报：「池里有重复条目」是我自己 harness 造出来的

当晚我一度在 README 里写下：

> ❌「微头条池 16 条目里有 6 个方向在 `toutiao-article-daily.py` 内置池与
> `toutiao_topics_extra.py` 扩写池中重复存在且内容完全相同」

**这是错的。** 根因 = 我的隔离 harness 写了：

```python
ALL_MICRO = base.MICRO_TOPICS_POOL + tx.EXTRA_MICRO_TOPICS   # ❌ 叠了两遍
```

`toutiao-article-daily.py` 在 import 时**已经**做了
`MICRO_TOPICS_POOL = MICRO_TOPICS_POOL + EXTRA_MICRO_TOPICS`（第 447 行）。
所以 `base.MICRO_TOPICS_POOL` **本身就已经是合并后的运行时池（10 条）**，
我再手动加一遍 `EXTRA_MICRO_TOPICS` ⇒ 得到 16 条「假重复」。

### 🔴 判别口诀

> **「池里有没有重复条目」必须读运行时合并后的 `base.MICRO_TOPICS_POOL`，
> 永远不要自己手动拼 `内置 + EXTRA`。**

手动拼 = 把脚本里 `+=` 之后的池再叠一次 ⇒ **必假报重复**。

**实测真值**：运行时 `MICRO_TOPICS_POOL` = **10 条、方向唯一、零重复**
（生成器内置 4 条：婆媳关系 / 养老金 / 子女不孝 / 老年婚姻
＋ 扩写文件 import 6 条：隔代育儿 / 工资卡 / 理疗骗局 / 丧葬费 / 退休金差 / 工龄错算）。
`TOPICS_POOL` 同理 = 10 条唯一。

> **同类陷阱**：任何「生产脚本 import 后 X 是什么」的判断，都要用
> `importlib` 加载**生产脚本本身**再看，**不要重新拼一遍它内部的合并逻辑**。
> 这与既有纪律「必须调用真实生产函数而不是在测试脚本里复刻逻辑」同源 ——
> **复刻 = 会漂移**。

## 三、锚点定位纪律：改文案前先跨三个源文件 `count()`

当晚的锚点分布：

```bash
for f in toutiao-article-daily.py toutiao_topics_extra.py toutiao_story_extensions.py; do
  echo "$f: $(grep -c '少记了3年' $f)"
done
# 生成器: 0   扩写池: 1   扩写段: 0
```

⇒ 锚点**只在扩写池**。只看生成器会得到 `count=0` ⇒ 容易误判成「内容没问题」而放弃修复。

**这正是既有纪律「锚点不确定时先跨三个源文件定位」的又一实例** ——
当晚第 3 次踩到「文件找错」这类坑（见 `references/pool-wide-scan-and-linter-syntax-death.md`）。
