# 缺陷六：「孤儿扩写」与「人工算账审计」（2026-11-04 头条号实测）

> 这是 `references/content-self-consistency-checking.md` 之后的**第六类内容质量失败模式**。
> 那一类讲「数字算不通、角色凭空多出」；这一类讲**更隐蔽的两个变种**：
> ① 扩写段落整个换成了另一个故事（孤儿扩写）
> ② 算术没错、但**跨段落的时间链/口径链**对不上（人工审计才能抓到）

## 一、为什么「全绿的审计」仍然会漏

2026-11-04 头条号那篇《72岁老人存了40万…》的审计结果**全绿**：

```
audit_rendered_article.py  → ✅ 全部检查通过（正文 2990 中文字，结构 10/10）
lint_content_consistency.py → ✅ 解析器自检通过 + ✅ 20 条选题未发现矛盾
脚本 exit 0 → HTML 渲染成功 → 飞书附件送达并回查确认
```

但手工通读全文并逐笔加数，**抓到 9 处读者可见硬伤 + 3 段孤儿扩写**。
这类缺陷的特征是：**每一处单独看都「像对的」，只有把整段读下来做算术才暴露**。

### 根因：审计工具查的是「单字段内自洽」，查不到「跨字段/跨时间链」

| 缺陷 | 现有工具为何漏掉 |
|------|-----------------|
| 62 岁起攒钱、每年 3.84 万、10 年到 40 万 ⇒ 72 岁（与标题一致）**但原文写 65 岁** | 没有任何一条规则把「起始年龄 + 年储蓄率 + 目标额」串起来 |
| 「女儿拿了 35 万，儿子拿了 15 万」= 50 万，而同篇声明总额 40 万 | `SPLIT_VS_TOTAL` 只认「一人X×N+剩下的Y」句式，认不出「甲拿了X万，乙拿了Y万」 |
| 主体写「退休金 3500」，扩写写「退休金 3200」 | 数值规则查的是**算式**，不是**同一属性在两处的取值是否一致** |
| 声明「一共住了十四个月」，明细 4.5+4+3=11.5 个月 | 无规则校验「合计 vs 分项」 |
| 声明「凑了 2 万请护工」，但护工 6000/月 × 2 月 = 1.2 万 | `CONTRIB_VS_FEE` 只在**同一句**里比对，跨句就漏 |

## 二、🔴 新缺陷类：孤儿扩写（ORPHAN_EXTENSION）

### 现象

扩写段落文件 `toutiao_story_extensions.py` 里，某条扩写**整个换成了另一个故事**：
主体故事讲孙大爷过户被儿媳赶走，扩写却写「老李头从房管局出来」；
主体故事B 讲赵大爷让儿子写借条，扩写B 却写「李桂香 55 岁换了一居室」。

**读者看到的是**：主角毫无预兆地换了个人，场景、年龄、性别、关系全部对不上。
这比数字算错更伤 —— 它让读者直接认为文章是拼凑/AI 生成的。

### 三个实例

| 方向 | 主体故事主角 | 扩写里出现的人 | 问题 |
|------|------------|--------------|------|
| 房产纠纷 | 孙大爷（69 岁，中学老师，过户被赶） | **老李头** | 凭空多出的人物 |
| 房产纠纷 | 故事B：赵大爷（71 岁，借条 80 万） | **李桂香**（73 岁，换一居室） | 整个故事被换掉 |
| 晚年孤独 | 故事B：老张（活动中心/义工/周六通话） | **老陈**（茶摊/补课） | 整个故事被换掉 |

### 检测规则的关键设计（踩了三次坑才做对）

**坑 1：不能按出现频次判主角。**
孤儿人物在自己的扩写段里往往出现得**更频繁**（老李头 2 次 vs 孙大爷 1 次），
按频次取「主角」会把孤儿当成主角，规则直接失效。

**坑 2：不能拿整篇单元比。**
故事B 的主角本来就和故事A 不同（周大爷 vs 老陈头）—— 拿整篇比会把
「周大爷」误报成孤儿；故事B 里合法提到故事A 的人物（「比孙大爷还大两岁」）
也会被误报。

**坑 3：人名抽取太贪婪会误报一堆非人名。**
初版正则抽出过「房管局」「红本子」「房子写」「张问刘婶」「元的周大爷」
—— 姓氏开头不代表人名。

### ✅ 正确口径

**按「A 对 A、B 对 B」配对比较**：只报「出现在扩写里、但对应主体故事里没有」的人名。
主体故事 = `story_a`（配 `ext_a`）、`story_b`（配 `ext_b`），分别比。

**人名抽取必须要求称谓后缀，且不许跨功能字**：

```python
# 姓 + 称谓后缀（中间 0 个字，不许跨「的/问/元」等功能字）
r'[' + _SURNAMES + r'](?:大爷|大妈|老师|师傅|婶|叔|姨|总)'
# 老 + 姓 + 头/儿/王/婶/姨/叔
r'老[' + _SURNAMES + r'](?:头|儿|王|婶|姨|叔)'
# 光杆 老X（老张/老李）只在出现 >= 2 次时才认，否则「老王」可能是普通词
```

再加泛称黑名单（老伴/老太太/老人/老大/老家/老同事…）与非人名黑名单。

## 三、🔴 人工审计：必须逐段通读 + 手动加数

**规则：审计内容产品时，除了「数字对不对」「角色存不存在」，还要问
「这句话跟当篇故事对得上吗」「这笔账加出来等于文中写的数吗」。**

2026-11-04 手工审计抓到的 9 处（全部在已投递产物里，全部绿灯）：

| # | 缺陷 | 修法 |
|---|------|------|
| 1 | 65 岁起攒钱（3.84 万/年）⇒ 75 岁才到 40 万，与标题「72 岁」矛盾 | 改 62 岁起 + 「头五年 20 万；又是五年，存到 40 万」 |
| 2 | 「存款差不多(40万)」但分家 35+15=**50 万** | 女儿改 25 万（25+15=40 ✔） |
| 3 | 「凑了 2 万请护工」vs 6000/月×2 月=1.2 万 | 改「凑了 1 万 2」 |
| 4 | 声明「住了十四个月」vs 明细 4.5+4+3=**11.5** | 改「十一个半月」（**同一段下一句也要一起改**） |
| 5 | 「小儿子每年回来两次」vs 汇总「来了 4 次」 | 汇总改 2 次；扩写里「老二在外地」同步改「老三」 |
| 6 | 1000/月×六年=6 万 vs 声称 15 万 | 补「学费/书本费/补习费另出」+ 明确「六年≈15 万」 |
| 7 | 主体「退休金 3500」vs 扩写「3200」 | 扩写改 3500 + 儿子 2000 = 5500，并删掉与「自己有房」矛盾的房租 |
| 8 | 「女儿每月来看两次」vs「每月15号固定来一次」；「一年给你5万」vs「5万美金」 | 统一口径 |
| 9 | 「儿子每月转 3000 美元补 2600 缺口」vs「一分没花全存着」 | 改「转 1 万块，刨去护工费和零头」 |

### 通读时重点盯的「时间链 / 口径链」

- **年龄链**：起始年龄 + 时间跨度 ⇒ 结束年龄，是否与标题一致
- **金额链**：总额 = 各分项之和（分家、养老出资、护工费）
- **时长链**：声明的合计月数/天数 = 各段之和
- **同属性取值链**：同一属性（退休金、养老院月费、房租、电话费）在主体段与扩写段是否同值
- **币种/口径链**：块 vs 美元 vs 万；「每月」vs「每年」vs「每次」
- **汇总链**：年终汇总的次数（来了 4 次）= 前面声明的频次（每年回来两次）

## 四、🔴 改源码时的批次原子性陷阱

**一条替换失败会让整批成功编辑全部丢失。**

2026-11-04 实测：一次脚本批量替换 16 处，其中 5 处因源文本与预期不符
（空格、引号、措辞差异）匹配为 0 —— 实现里写的是「全部成功才落盘」，
结果 **11 处已成功的编辑也被一起丢弃**，得重做一遍。

**规则：**
- **逐条落盘**：每条替换成功后立即写文件，失败的单独列出，不回滚已成功的
- **匹配失败时先打印实际源文本再改**：`src.find(key)` 拿到上下文，
  比猜原文可靠得多
- 改完跑 `py_compile` 三个源文件

```python
for old, new in pairs:
    c = src.count(old)
    if c == 1:
        src = src.replace(old, new)
        write_file(path, src)      # ← 逐条落盘，互不影响
        print('OK  ', old[:40])
    else:
        print('FAIL x%d %s' % (c, old[:60]))   # 只报告，不回滚
```

## 五、给 linter 新增规则时的自检纪律

新写的规则**必须**在 `_self_test()` 里配「正例不报 + 反例必报」两条算例，
否则你不知道规则本身是否正确（本次新增 3 条规则，第一次跑就 4 条自检失败）。

**退出码语义保持不变**：
- `0` = 内容干净
- `1` = 内容有问题
- `2` = **工具自己坏了**（自检失败）—— 与内容问题严格区分

**自检失败时的调试顺序**：先看自检输出（工具坏了），**再**看内容问题。
绝不能因为「规则报了假阳性」就去改本来写对的文案。

**新增规则的通用教训：**
- 数值规则要**分清单位口径**：`40`（捕获组不含「万」）本身是「万」，
  `十八万七` 才是「元」—— 混用会差 1e4
- 匹配「一个月 X 元」时，**必须确认 X 紧邻「护工」二字**，
  否则会把「养老院月费 4200」当成护工费
- 窗口里出现**多个出资方**时无法判定 → 跳过，不要硬判
