## 一、工具死亡的第三种形态：`SyntaxError`（条件表达式缺 `else`）

### 实测

```bash
$ python3 scan_pool_defects.py --pool ... --extensions ...
  File ".../scan_pool_defects.py", line 149
    ea = (ext[0] if ext and len(ext) > 0 and ext[0]) or ''
          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
SyntaxError: expected 'else' after 'if' expression
$ echo $?
1
```

**根因**：三元表达式写成了 `(X if cond) or ''` —— **Python 的条件表达式必须有 `else` 分支**。
`(X if cond)` 在语法上就是非法的（`cond` 后面直接跟 `)`）。

正确写法：

```python
ea = ext[0] if (ext and len(ext) > 0 and ext[0]) else ''
eb = ext[1] if (ext and len(ext) > 1 and ext[1]) else ''
```

⚠️ **注意**：`(X if cond) or ''` 这个写法看起来像「取 X 或空串」，但它**根本编译不过** ——
不是「优先级陷阱」，是语法错误。见到 `(x if y) or z` 直接改成 `x if y else z`。

### 判别（沿用既有纪律，扩展版）

| stderr 形状 | 判定 | 应对 |
|---|---|---|
| traceback + 末行 `SyntaxError` | 工具文件本身坏了 | **修工具，别碰文案** |
| traceback + `NameError: xxx 未定义` | 工具内部坏了 | 修工具 |
| 无 traceback + 有规则名 + 命中项 | 内容有问题 | 改文案 |
| stdout 空 + stderr 有 traceback | 工具崩了 | 修工具 |

**口诀：先看 stderr 有没有 traceback，再决定动谁。** exit 1 有两种完全相反的含义。

### 🔴 附带教训（第二次踩到同一个坑）

`scan_pool_defects.py` 是 **2026-11-18** 才落地的，**当晚（11-19）是第一次真正跑它** ——
一跑就是坏的。**这与 11-17 的 `verify_cross_night_collisions.py` 完全同款**：
落地后无人调用 ⇒ 静默腐烂 ⇒ 首次调用即失败。

> **固化纪律**：任何**新落地的校验器**，在同一次会话里必须用**真实生产参数**跑一遍
> 并记录退出码，否则不许写进报告的「工具链状态」那一行。
> **连续两晚各踩一次 ⇒ 这是系统性习惯问题，不是运气。**

## 二、🔴🔴 扫描器的三重「假绿」：报「无命中」≠ 没问题

2026-11-18 的报告已经明确指出：微头条《丧葬费》存在否定承诺硬伤
（标题断言「三个子女**一分没出**」，正文后段却写「小儿子**转了5000块**过来」）。
11-19 修完之后跑 `scan_pool_defects.py` —— **段⑥「否定式承诺被正文推翻」报「无命中」**。

**假绿。三处漏报，逐个查出来：**

### 漏报 1：段⑥ 只认「同一动词」

```python
# 旧实现
neg_v  = re.search(r'[出给拿花掏转寄交管来回问]', neg)     # 标题「一分没出」→ 出
done_v = re.search(r'[出给拿花掏转寄交管来回问]', d.group(0))  # 正文「转了5000」→ 转
if neg_v and done_v and neg_v.group(0) == done_v.group(0):   # 出 != 转 ⇒ 不 fire
```

标题说「没**出**」，正文说「**转**」—— 动词不同 ⇒ 规则判定「不矛盾」。

**修法：加一条粗筛兜底**（转账类动词 + 邻近金额），并按「正文有没有写明解释句」分级：

```python
TRANSFER_ACT = re.compile(r'(?:转了|给了|掏了|寄了|汇了|打过来|打了钱|交了)')
DISCLAIMER  = re.compile(r'(?:不算|不算是|不属于|不是他出|不是她出|不算他|不算她|'
                         r'是[^。]{0,8}补的|后补|事后补)')
NUM_RE      = re.compile(r'(\d+(?:\.\d+)?)\s*(?:块|元|万|块钱)')
```

命中时输出 `note`：
- 「未见解释句 ⇒ **疑似真缺陷**」
- 「已见解释句 ⇒ 大概率已按缺陷二十一修过」

⚠️ 仍是**粗筛不是判定器** ——「出了丧葬费」≠「出了份子钱」，正则分不出主体与语义。

### 漏报 2：段① 按句号切分把「她说：」前缀粘进句子

```python
for sent in re.split(r'[。！？；\n]', hook):
    ns = norm(sent)
    if len(ns) >= 6 and ns in nb:   # 整句 in 正文
```

钩子 `她说：'孩子的心是真的，可手不在你身边。'这句话我想了很久。`
按句号切开 ⇒ 第三块是 `她说：'孩子的心是真的，可手不在你身边` ——
**「她说：」前缀被粘在引语前面** ⇒ 整句不再是正文的子串 ⇒ **漏报**。

**修法：额外单独检测钩子里的每一段引语**（引号内 ≥6 字）是否在正文出现：

```python
for q in quotes(t.get('hook') or ''):
    nq = norm(q)
    if len(nq) >= 6 and nq in nb:
        res['1_hook_echo'].append({... 'note': '引语级复读（设计约束）：人工核对兑现点是否带新细节'})
```

### 漏报 3（最隐蔽）：**微头条池根本没被扫**

```python
pool = list(getattr(mod, 'TOPICS_POOL', []) or [])   # ← 只有长文池！
```

段⑥（否定承诺）在**微头条池**里最容易命中（微头条标题短、常带「一分没出」这类断言），
而扫描器**只装配了长文池** ⇒ 微头条池的所有缺陷 **永远不会被检出**。

**修法**：

```python
micro_pool = list(getattr(mod, 'MICRO_TOPICS_POOL', []) or [])
res = scan(pool, ext_map)
if micro_pool:
    res_micro = scan(micro_pool, ext_map)
    for k, v in res_micro.items():
        for item in v:
            item['pool'] = '微头条'
        res[k].extend(v)
```

⚠️ 微头条正文在 `content` + `micro_dialogue`，与长文的 `story_*` 字段结构不同 ——
`scan()` 内部已有 `if g('content')` 分叉，装配口径不用改。

### 三条漏报的共性

**扫描器报「无命中」时，要先确认它「看得到」那一段内容。**
三处漏报里，两处是**装配口径**问题（一处漏扫微头条池、一处引语前缀粘连），
一处是**判定口径**问题（只认同一动词）。
⇒ **「报 0 命中」要先做反向验证**（见第四节），不能直接当「干净」。

## 三、🔴 引语级复读 vs 散文级复读 —— 本轮改错了 2 处的教训

### 场景

11-19 通读全池 8 字重叠，扫出 12 处。我按「钩子整句复读 = 缺陷」的既有纪律，
改了两处：

| 方向 | 我改的 | 结果 |
|---|---|---|
| 再婚财产 | `ext_a` 里 25 字引语复读 → 改成「房子我给得起，我想要的是晚上有人搭句话」 | ❌ **lint exit 1** |
| 房产纠纷 | 钩子引语「您确定要过户吗？」在正文出现 → 改成「您真要过户？」 | ❌ **lint exit 1** |

lint 报错：

```
【再婚财产】
  [HOOK_PROMISE] 钩子/标题承诺的引语「我不是要跟孩子们争房子，我是想要一个能睡得着觉的地方。」在正文里没有
【房产纠纷】
  [HOOK_PROMISE] 钩子/标题承诺的引语「您确定要过户吗？」在正文里没有
```

### 根因：`HOOK_PROMISE` 是**硬约束**，与「复读」规则直接冲突

`HOOK_PROMISE`（`lint_content_consistency.py`）要求：
**钩子/标题里的每一段引语，必须原样出现在装配后的正文里。**

所以 ——

| 重叠类型 | 判定 | 依据 |
|---|---|---|
| **引语级**（重叠片段落在引号内的对白里） | **设计约束，不是缺陷** | `HOOK_PROMISE` 强制要求它出现；删掉就触发 lint exit 1 |
| **散文级**（重叠片段是叙述句，不是对白） | **真缺陷** | 读者在两屏内看到同一段话两遍 |

### ✅ 正确的修法（引语级复读）

**保留钩子原句 + 在正文兑现点补新细节**（动作/心理/后果），让第二次出现不再是复制粘贴：

```
远居赡养（修前）：那天晚上她跟老王说了句心里话：'孩子的心是真的，可手不在你身边。'老王听完没接话……
远居赡养（修后）：那天晚上她跟老王说了句心里话：'孩子的心是真的，可手不在你身边。'
                    这句话她在电话里跟儿子说过三回，每回都说到一半咽了回去。
                    这回老王听完没接话，只是把水杯往她手边推了推。
```

⇒ 引语仍在正文（`HOOK_PROMISE` 过），但兑现点**带新细节**，读者不会觉得是复制粘贴。

**散文级复读**才直接改那一句（本轮：房产纠纷 `story_b_ending`「你就什么都不是了」
↔ `viewpoint` 同句 9 字 → 结局改「你就成了外人」）。

### 判定配方（可直接复用）

```python
Q = re.compile(r'[「『""\'\']([^」』""\'\']{2,})[」』""\'\']')
def cjk(s): return re.sub(r'[^一-鿿]','',s or '')

# 对每处重叠片段问：它落在某段引语里吗？
in_quote = any(seg in cjk(q) for f in (a,b) for q in Q.findall(fields[f] or ''))
# in_quote=True  → 设计约束：别删，改成「保留 + 补新细节」
# in_quote=False → 真缺陷：改散文那一句
```

⚠️ **散文级复读也可能是有意呼应**（如随礼人情「你存进去就能取出来」是点题式回扣）。
**逐条人工核对后再改。**

### ⚠️ 另一条铁律：改之前先跑 lint

本轮两处错误修改都是**改完跑 lint 才发现冲突**。正确顺序：

```
1. 先读懂 HOOK_PROMISE 的语义（它要求什么）
2. 改
3. 立刻跑 lint（单独看退出码）
4. 若 exit 1 且是 HOOK_PROMISE ⇒ 我的修改违反了硬约束 ⇒ 回退并换修法
```

**回退纪律**：回退要**逐条**做（不是 `git checkout` 全量）——
本轮 4 处修改里有 2 处正确、2 处错误，全量回退会把对的也丢掉。

## 四、🔴 反向验证：规则「报 0」必须先证明它「会 fire」

**纪律升级**：`HOOK_PROMISE` 的教训是「只跑干净内容 exit 0 证明不了规则接上了」。
本轮把它推广到**粗筛脚本**：

> **「扫描器报无命中」不等于「内容干净」—— 必须造一个已知有缺陷的反例，
> 断言它**会**被报出来。**

实测做法（用修复前的备份当反例）：

```python
# 反例 = /tmp/toutiao_bak_1119/ 里的修复前版本
old = "…回到家，小儿子转了5000块过来，附言写着：'姐，先给一部分。'女儿收了，没回话。…"
new = old.replace("女儿收了，没回话。", "女儿收了，没回话。这5000是丧事办完之后他补的份子钱，不算他出的丧葬费。")

for label, content in (('修复前', old), ('修复后', new)):
    r = check_negative_promise(title, hook, content)
    print(label, len(r), r[0]['note'] if r else '')
```

实测输出：

```
修复前: 1  粗筛：动词不同（出 vs 转）… 未见解释句 ⇒ 疑似真缺陷
修复后: 1  粗筛：动词不同（出 vs 转）… 已见解释句 ⇒ 大概率已按缺陷二十一修过
```

⇒ **规则确实会 fire**，且能区分「已修 / 未修」。

⚠️ **注意**：修好后规则**仍然命中**（这是粗筛的正常行为）——
**命中 ≠ 缺陷**。区别体现在 `note` 的分级标注里。
**这正是「粗筛不做成硬规则」的价值**：不逼着人去改本来正确的文案。

## 五、本轮新发现的缺陷族（未修，留给下一轮）

### 量词级承诺失配 —— `HOOK_PROMISE` 的第三个盲区

当晚长文（兄弟姐妹）：

- **标题**：「小女儿**只说了一句话**」
- **钩子**：「她爸走的那天，她**一句话都没说**」
- **结局**：「她心里那句话，**到最后也没说出口**」

读者会直接问：**到底是说了还是没说？**

### 盲区成因

`HOOK_PROMISE` 只查**引语**与**阿拉伯数字**：
- 「三个儿女」里的「三个」是**量词不是数字** ⇒ 查不到（11-12 已知）
- 「只说了一句话」是**量词 + 动词短语** ⇒ 同样查不到

### 修法方向（下一轮）

**改标题或改钩子/结局其一，并同步 `golden1`**：
- 方案 A：标题改「小女儿**一句话没说**」（与钩子、结局一致）
- 方案 B：结局改成她**真的说了一句**（则标题与钩子都要改）

⚠️ 改完必须重跑 lint（`HOOK_PROMISE` + `GOLDEN_ECHO`）+ 量 CJK。

### 通读清单新增第 ⑰ 条链：**量词/动作承诺链**

> 「标题里的**人数、次数、动作量词**（一句话/一个/三个/两次）在正文兑现了吗？」

扫描配方（粗筛）：

```python
# 标题里的量词短语 → 正文是否出现对应数量的动作
for m in re.finditer(r'(只|一共|连)?([一二两三四五六七八九十\d]+)(句|个|次|口|天|年|遍)',
                     title):
    print(m.group(0))
```

## 六、本轮完整检查清单（可直接复用）

1. **新落地的校验器必须真跑一次**（连续两晚各踩一次同款 ⇒ 习惯问题）。
2. **判别「工具死了」看 stderr 的形状**，不看退出码。
3. **扫描器报「无命中」前先做反向验证**（造已知反例，断言它会 fire）。
4. **改文案前先跑 lint** ⇒ 确认没有违反 `HOOK_PROMISE` 等硬约束。
5. **引语级重叠 = 设计约束，散文级重叠 = 真缺陷**（判定配方见第三节）。
6. **引语级复读的修法 = 保留原句 + 兑现点补新细节**（不是删、不是换说法）。
7. **改错了要逐条回退**，不全量回滚（保住同批里改对的）。
8. **微头条池同样要扫**（`MICRO_TOPICS_POOL`），别只扫长文池。
9. **通读清单新增第 ⑰ 条链「量词/动作承诺链」**。
