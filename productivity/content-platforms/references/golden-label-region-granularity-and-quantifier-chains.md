## 一、🔴 根因 A：`_golden_labels()` 的 region 划分过粗 ⇒ 阈值再准也会指错出处

### 现象

11-20 已经把 `_golden_labels()` 的中性阈值从 `0.05` 提到 `0.10`（「宁可模糊也不说假话」）。
但 11-22 仍抓到 **3 处标签指错**，且**不是阈值问题** —— 是**候选 region 的划分方式**问题。

### 11-22 的旧实现（region 太粗）

```python
# ❌ 旧版：只有两个粗 region
REGIONS = [
    ('A正文', story_a + story_a_dialogue + story_a_ending),   # ← 正文/对话/结局糊成一坨
    ('B正文', story_b + story_b_ending),                       # ← 同上
]
```

**问题**：一个 region 内部的**子段落**（`story_a` 正文 vs `story_a_ending` 结局）**权重被平均掉了**。
当金句实际出自 `story_b` 的**正文**而不是 `story_b_ending` 时，
bigram 重叠率在「B正文」这个糊成一坨的 region 上算出来**分数不够高**，
落到第二名「故事A正文」或中性标签 ⇒ **标签指错**。

### 11-22 实测：3 处标签纠正前后对照

| 方向 | golden | 标签（修前） | 标签（修后） | 真实出处 |
|---|---|---|---|---|
| 再婚财产 | golden2 | 故事B结尾 ❌ | **故事B正文** ✅ | 出自 `story_b` 正文段，不是 `story_b_ending` |
| 远居赡养 | golden2 | 故事B结尾 ❌ | **故事B正文** ✅ | 同上 |
| 随礼人情 | golden3 | 故事B结尾 ❌ | **故事B正文** ✅ | 同上 |

**三处全是同一个模式**：金句出自故事B的**正文**而非**结尾**，
旧实现的「故事B结尾」region（= `story_b + story_b_ending` 合并）评分被稀释 ⇒ 指错。

### 修法：把 region 拆细到「子段落」级

```python
# ✅ 新版：7 个 region，每个对应一个可独立命名的子段落
_REGIONS = [
    ('A正文',   story_a),
    ('A对话',   story_a_dialogue),
    ('A结尾',   story_a_ending),
    ('B正文',   story_b),
    ('B结尾',   story_b_ending),
    ('观点',    viewpoint),
    ('行动',    action),
]
```

**拆分原则**：**每个 region 必须是一个语义上可以独立被引用的段落单元**。
合并的 region 权重会被稀释；拆开后 bigram 重叠率才如实反映出处。

### ⚠️ 关键判断：拆细之后，**中性标签仍然必须保留**

拆细 region 会让**分数差距变大**（best 与 second 拉得更开）⇒
中性阈值 `0.10` 会**更难触发**。但这不意味着可以删掉中性分支：
- 某些金句确实是**跨段提炼**的（从 A 和 B 各取一半），
- 某些金句是**重写**而非摘录（措辞与任何一段都不重合）。

**保留规则**：`if (best - second) < 0.10: label = "文章金句"` —— 宁可模糊也不说假话。
**拆细与中性阈值是两条独立的正交修复，不能互相替代。**

### ⚠️ 副作用：拆细后**同一句话可能命中多个 region**

金句是正文某段的**摘录**时，它会同时与「A正文」和「A对话」有高重叠
（对话经常是正文里那句话的延续）。修法：

- 用 **best - second 的差距**而非 **best 的绝对分数**来决定标签（差距小 ⇒ 中性）；
- `second` 必须是**除 best 之外所有 region 的最高分**，包含同属一个故事A的其他子段；
- 这样「A正文 vs A对话」分数接近时自动落中性，而不是随机挑一个。

### 验证方式（不必等渲染）

```python
# 隔离 harness 里对 10 个方向各渲染一次，打印每条池条目的
# (golden1, golden2, golden3) → 标签三元组，人工核对是否与正文实际出处一致
```

11-22 用这个方法在 10 个方向上验证，纠正 3 处，其余 7 个方向标签保持不变或本就中性。

## 二、🔴 根因 B：量词级承诺链断裂（第 ㉓ 条链「量词承诺链」的三个新变体）

`HOOK_PROMISE` 只认**引号内引语** + **阿拉伯数字**。量词（「两个孩子」「一样东西」「三个孩子」）**完全在覆盖之外**。
11-12 已知「三个儿女」是盲区；11-22 又抓到**三种新变体**：

### 变体 ① 金句里的「人数」与正文的实际人数不符（人数链）

> 实例（再婚财产）：金句写「这一步晚了，**两个孩子**就都凉了」，
> 但正文里赵叔实为**三个孩子**（大女儿 / 二儿子 / 小女儿）⇒ **读者数一数就发现金句在撒谎**。

**修法**：把金句的集合称谓改成**不锁死人数**的写法（「一家人」「他们」）。
⚠️ **不要改成「三个孩子」** —— 因为人数链一旦改动，可能连带正文里其他引用该数字的段落。
**金句是提炼物，改金句；不要动正文的数字链。**

### 变体 ② 钩子里的「数量」与它自己列出的清单不符（自相矛盾）

> 实例（再婚财产）：钩子写「带了**一样东西**」，
> 紧接着却列了**房产证 + 账本两项** ⇒ **读者在同一段里就发现钩子数错了**。

**修法**：钩子的数量词必须与**它自己后面列的清单条数**一致。
这类错误**完全在钩子内部**，不需要跨字段比对 —— 是最容易被人工通读抓到的类型，
但 `HOOK_PROMISE` 永远报不出来（钩子引语兑现了，只是数量词说错）。

### 变体 ③ 标题 ↔ 钩子 ↔ 正文 三方对「事实性名词」的时态/状态不一致

> 实例（再婚财产）：标题写「62岁老伴**婚前**把房子改成了新伴侣的名字」，
> 但正文只写到「咱们**先**把证领了」的**提议** —— 从未写证真领了。
> ⇒ 标题断言了一件正文里没发生的事（读者读完全文找不到「婚前」这个时间点）。

**修法（重要）**：标题里断言的事实，正文**必须真的写过那件事**，否则就把标题改成
**只断言正文确实兑现的两件事**：

```
❌ 「62岁老伴婚前把房子改成了新伴侣的名字，大女儿把老人告上了法庭」
✅ 「62岁老伴要再婚，把房子改成了新伴侣的名字，大女儿把老人告上了法庭」
```

⚠️ **注意这不是「把钩子写软」** —— 钩子没承诺「领证」，是**标题**越界了。
`HOOK_PROMISE` 查标题时只查引语词与阿拉伯数字，「婚前」是**事实性名词**⇒ 零覆盖。

### 变体 ④ 量词级承诺在**三处各说各的**（11-19 已记的量词链，此处是它的完整形态）

> 实例（兄弟姐妹）：标题「小女儿**只说了一句话**」 vs 钩子「她**一句话都没说**」 vs 结局「到最后**也没说出口**」
> ⇒ 三处互相打脸。**修法：以钩子为唯一真源**（钩子是读者点进来的理由），
> 标题改成「分家那天小女儿**一句话没说**」，与钩子/结局/正文四处一致。

### 变体 ⑤ 金句里的「字数」与引语实际字数不符（字数链）

> 实例（兄弟姐妹）：金句写「只说了**四个字**'谁也别动'」，
> 但正文原话是「**这个谁也别动**」（**六个字**）⇒ 读者数一下就知道对不上。

**修法**：**不要去数并改数字**，而是把金句的「数字 + 引语」改成**不含字数断言**的表述：

```
❌ 「只说了四个字'谁也别动'」
✅ 「只交代了一句'这个谁也别动'」
```

**通用原则：凡是需要读者「数一下」才能验证的断言（金句里报字数、报条数、报人数），
一律改写成不可数的定性表述。** 读者在手机上不会真的去数字数，但一旦对不上就会怀疑整篇是编的。

## 三、🔴 变体 ⑥：同角色在**同一篇内**的称呼漂移（跨字段称谓链的新形态）

11-12 / 11-08 记录的是「扩写段 vs 主体段」的称呼冲突（跨文件）。
11-22 抓到**同方向内**的漂移：

> 实例（兄弟姐妹）：故事B 的第三个孩子叫「**小儿子**」（深圳），
> 但**扩写段**里同一场景写成「**老三**」⇒ 同一篇里同一个人有两个名字。

**修法**：统一回主体用词（「小儿子」）。**不要反过来改主体** ——
主体段是读者先看到的，是称呼的**基准**。

⚠️ 注意这与「孙辈/子女称谓链断裂」（11-17）是**两个不同的族**：
- 11-17：**亲属关系本身错**（孙子叫爷爷「爸」）⇒ 改称呼
- 11-22：**同一个人被叫了两种名字**（小儿子 / 老三）⇒ 统一到基准名

## 四、通读清单扩容：12 条链 → **18 条链**（本次新增 ⑱–㉔）

| # | 链 | 问什么 | 本次实例 |
|---|---|---|---|
| ⑱ | **人数链** | 金句/钩子说几个人，正文真的有几个人？ | 金句「两个孩子」vs 正文三个孩子 |
| ⑲ | **数量自洽链** | 钩子说「带了 N 样」，后面真的列了 N 样吗？ | 「一样东西」vs 列了两项 |
| ⑳ | **标题事实名词链** | 标题的「婚前/领证/过户」这类事实名词，正文真写了吗？ | 标题「婚前」vs 正文只写了提议 |
| ㉑ | **量词级承诺三处链** | 标题/钩子/结局对「一句话/一次」的说法一致吗？ | 只说了一句话 / 一句话都没说 / 没说完 |
| ㉒ | **字数断言链** | 金句报的字数与引语实际字数一致吗？ | 「四个字」vs 实际六个字 |
| ㉓ | **金句标签 region 粒度链** | 金句标签指到的子段落，真的是它的出处吗？ | golden2 出自 B正文 却标「故事B结尾」 |
| ㉔ | **同篇称谓唯一链** | 同一角色在同一篇里只有一个名字吗？ | 小儿子 / 老三 |

**⑱–㉒ 的共同点**：全部是「**读者可以用手指点着数出来**」的断言
（人数、条数、字数、次数）—— 这类断言在头条中老年读者群体里**特别容易被当场戳穿**，
因为他们真的会数。**通读时优先核这一类。**

**⑬–㉔ 的共性**：全部是「量词 / 计数 / 命名」维度的承诺 ——
`HOOK_PROMISE`（引语 + 阿拉伯数字）之外的**第二类数字承诺**。

## 五、🛠️ 扫描配方（可复用）

```python
import re

# ① 人数 / 条数量词（中文数字 + 一/几）
QUANT = r'(只|一共|连|总共)?([一二两三四五六七八九十\d]+)(句|个|次|口|天|年|遍|样|件|条|块|口人|个人|个孩子|个子女)'

def quantifiers(text):
    """抽出文本里所有量词级数字断言，供人工核对。"""
    return [(m.group(0), m.start()) for m in re.finditer(QUANT, text or '')]

# ② 字数断言链：金句里报的字数 vs 引语实际字数
m = re.search(r'([一二两三四五六七八九十\d]+)个字?[，,]?[‘\'"]([^’\'"]{1,20})[’\'"]', golden)
if m:
    claimed = _cn_num(m.group(1))
    actual = len(re.findall(r'[一-鿿]', m.group(2)))
    if claimed != actual:
        print('字数链断裂：', m.group(0), '→ 声称', claimed, '实际', actual)

# ③ 钩子内部数量自洽：钩子说「N 样/个」→ 数后面分号/顿号分隔的清单条数
```

⚠️ 这些是**粗筛**，不是判定器 —— 命中 ≠ 缺陷（设计约束、并列多项、模糊指代都会误报）。
