## 一、🔴 缺陷二十一：标题承诺了「否定事实」，正文却做了这件事

### 现象

微头条《老伴走了，丧葬费三个子女一分没出，最后是大女儿一个人掏的》：

- **标题断言**：「三个子女**一分没出**」
- **正文首段**：「她垫的钱，弟妹两个**一分没出**。」← 与标题一致
- **正文后段**：「小儿子转了 **5000** 块过来。」← **推翻了前面的断言**

读者读到后半段会立刻回头看标题：「不是说一分没出吗？这 5000 是什么？」
**这是读者可见的自相矛盾，比数字算错更刺眼** —— 因为它出现在标题里，
标题是读者点进来的唯一理由。

### 为什么现有全部规则测不到

| 规则 | 查什么 | 为什么漏掉这一条 |
|---|---|---|
| `HOOK_PROMISE` | 钩子/标题里的**引语**与**数字**必须在正文兑现 | 标题里的「一分没出」是**没有数字的否定式断言**；规则只认引号词和阿拉伯数字 ⇒ 完全够不着 |
| `SPLIT_VS_TOTAL` / `SUM_VS_HALF_CLAIM` | 明细之和 vs 声明总额 | 这里没有「明细」可加总 —— 是**存在性**冲突，不是**算术**冲突 |
| `GOLDEN_ECHO` | 金句被正文整句复读 | 与金句无关 |
| `audit_rendered_article.py` | 字数 / 结构 / 配图 / 标签 | 不读语义 |

**根因：现有规则里所有「承诺兑现」类的检查都默认承诺是一个「存在」**
（某个数字要出现、某句话要出现）。**但否定式承诺（"X 没做 Y"）一旦被正文推翻，
同样会让读者觉得整篇是编的**，而且这类缺陷在「算账题材」（头条中老年读者
最爱）里最容易出。

### 检测配方（可直接复用）

```python
import re

# ① 否定式承诺的触发词表 —— 「没/未/不 + 动作」的表述
NEG_PATTERNS = [
    r'一分没出', r'一分没出[来钱]', r'没出[过]?一?分?',
    r'没(?:出|给|拿|花|掏|管|过问|来看|回|来过|理会|吭声|露面)',
    r'未(?:出|给|拿|花|掏|管|过问|来|回)',
    r'不(?:管|过问|理会|吭声|露面|参与|掺和)',
    r'一(?:分|个)(?:钱)?也?没',
    r'没(?:一个|一笔)(?:人)?出',
]

# ② 标题/钩子里出现否定式承诺时，记下「被否定的动作」
#    然后在正文里找这个动作是否**真的发生了**
def check_negative_promise(title, hook, body, direction=''):
    claim = f'{title} {hook}'
    body_n = re.sub(r'[^\u4e00-\u9fff]', '', body)

    hits = []
    # 「没出/没给」这类：正文若出现该动作的「完成态」（出了/给了/转了/掏了）
    for m in re.finditer(r'没(?:出|给|拿|花|掏|管|来|回|过问)([^。！？\n]{0,14})', claim):
        # 抽出被否定的动作对象，例如「没出」→「钱」
        obj = m.group(1)
        # 正文里找同义动作的完成态
        for done in re.finditer(r'(出了|给了|拿了|花了|掏了|转了|寄了|交了|管了|来了|回了|过问了)([^。！？\n]{0,14})', body):
            if obj and (obj[:2] in done.group(0) or done.group(2)[:2] in obj):
                hits.append((direction, m.group(0), done.group(0)))
                break
    return hits
```

### 实测命中（11-18 当晚）

```
[丧葬费] 标题「一分没出」，正文出现转账: ['5000']
      句: 她垫的钱，弟妹两个一分没出。
```

### 修法（三个选项，按优先级）

1. **改后文**：把「小儿子转了 5000 块过来」改成不构成出资的动作
   （例如「小儿子寄了两条消息」），或明写「这 5000 是丧事之后补的份子，
   不算他出的丧葬费」（**保留标题断言，同时解释**，是头条读者最爱的写法）。
2. **改标题**：把「一分没出」改成与正文一致的说法（如「三个子女只出了一个」）。
3. **⚠️ 不要把否定式承诺改成模糊词**（如「基本没怎么管」）—— 那是在把
   钩子写软，违反既有纪律（钩子优先级高于正文顺滑）。

### ⚠️ 这条规则的定位：**它不是通用 linter 规则，是通读清单条目**

否定式承诺的判定需要理解「这个动作到底算不算履行了承诺」——
「寄了 5000 丧葬费」和「寄了 5000 份子钱」在**语义上不是一回事**，
但正则分不出来。**建议做法**：把它做成**通读清单的一条链**（见下），
同时在扫描脚本里做**关键词粗筛 + 人工核对**，而不是直接做成硬规则。
（做成硬规则必然产生大量假阳性，然后后患是「为了让规则闭嘴去改本来正确的文案」。）

## 二、人物身份撞车扫描（姓氏 / 年龄）—— 新增维度

故事A 与 故事B 是**两个独立故事**，但读者在同一篇文章里连续读，
**如果 A、B 用了同一个姓氏或同一年龄**（尤其是同一个称呼），
读者会以为「这是同一个人在讲两件事」⇒ 故事B 的转折被稀释。

### 实测命中（11-18 当晚）—— 全部为**假阳性**，但值得扫

| 方向 | 命中 | 人工核对结论 |
|---|---|---|
| 赡养义务 | A/B 同名：`王阿姨` | **假阳性** —— B 开头是「她的做法跟王阿姨完全不一样」的**对比式提及**，不是同一角色 |
| 房产纠纷 | A/B 同名：`孙大爷` | **假阳性** —— 同上 |
| 随礼人情 | A/B 同名：`老周头` | **假阳性** —— 同上 |
| 晚年孤独 | A/B 同龄：`75` | **假阳性** —— 年龄相同但场景完全不同，且一个是「同龄的参照」 |
| 远居赡养 | A/B 同龄：`68` | **假阳性** —— 同上 |

**⚠️ 这 5 处全部不改** —— 这正是既有纪律「**假阳性必须逐条人工确认，
不能看到告警就改文案**」的又一次应用。

### 检测配方

```python
import re

def _names(txt):
    """抽取人名/称呼：要求带称谓后缀，避免抽出「房管局」「红本子」这类非人名。"""
    out = set()
    for m in re.finditer(r'[一-龥]{1,3}(?:大爷|大娘|阿姨|叔叔|婶儿|婶子|大哥|大姐|大哥|老头|老太婆|师傅|老师|医生|会计|律师|姑娘|小伙)', txt or ''):
        out.add(m.group(0))
    return out

def _ages(txt):
    return set(re.findall(r'(\d{2})\s*(?:岁|周岁|那年|年迈)', txt or ''))

# A/B 各扫一遍，交集即撞车
for t in pool:
    d = t['direction']
    a = t['story_a'] + t['story_a_dialogue'] + t['story_a_ending'] + (ea or '')
    b = t['story_b'] + t['story_b_ending'] + (eb or '')
    same_name = _names(a) & _names(b)
    same_age  = _ages(a) & _ages(b)
    if same_name or same_age:
        print(f'⚠️ [{d}] 同名={same_name or "-"} 同龄={same_age or "-"}')
```

**⚠️ 三个必须注意的口径**（今晚踩到的）：

1. **人名抽取不许跨功能字** —— 否则抽出「元的周大爷」「房管局」这类碎片
   （既有教训，见 `orphan-extensions-and-hand-arithmetic-audit.md`）。
2. **必须要求称谓后缀** —— 「王阿姨」「老周头」这类才算是人名。
3. **「对比式提及」是合法的同名来源** —— B 故事开头拿 A 故事的人做参照
   （「她的做法跟王阿姨完全不一样」）是**双故事对比论证法的标准写法**，
   **不是撞车**。⚠️ 判别方法：看同名是否出现在**该故事自己的叙述主体**里
   —— 只在**对比提及句**里出现 ⇒ 假阳性；出现在 B 的动作/结局里 ⇒ 真撞车。

### 顺带一提：**年龄撞车比姓名撞车更弱**

两篇故事主角同为 68 岁**不是缺陷** —— 中老年题材里 68 岁是主力年龄，
撞车是必然的。年龄只有在**同一篇里两个角色应当区分**（如「他68岁，
她也是68岁」）时才是问题。**建议：年龄扫描只做提醒，不进通读清单。**

## 三、六段式全池扫描脚本（可复用组装方式）

今晚的扫描脚本（`/tmp/defect_scan_1118.py`）分成 6 段，每段对应一类缺陷。
这个**分段式组装**值得固化 —— 它把「一个大脚本」拆成 6 个独立可失败的段，
一段报错不影响其余段：

| # | 段名 | 查什么 | 当晚结果 |
|---|---|---|---|
| ① | 钩子整句复读（含扩写段） | 钩子引语在正文出现 >1 次 | 3 处（赡养义务/再婚财产/远居赡养） |
| ② | 标题引语 vs 正文 | `HOOK_PROMISE` 的设计约束项 | 1 处（房产纠纷）—— **标注「设计约束」，不改** |
| ③ | 金句 ↔ 正文复读（8 字，含扩写） | `GOLDEN_ECHO` 阈值 | 1 处（赡养义务 8 字） |
| ④ | 人物姓氏撞车 | A/B 同名 | 3 处 —— 全假阳性 |
| ⑤ | 年龄撞车 | A/B 同龄 | 2 处 —— 全假阳性 |
| ⑥ | 微头条：标题承诺 vs 正文 | **否定式承诺** | 1 处真缺陷（丧葬费 5000） |

**组装要点**：

- **② 的输出必须显式标注「设计约束」**，不能和真缺陷混在同一张清单里
  —— 否则修的时候会去改「钩子必须兑现承诺」的地方。
- **④⑤ 的命中默认是待核对**，不是待修（见上）。
- **① 与 ③ 的阈值不同**（① 整句、③ 8 字公共子串）—— 别用同一个判定函数。

## 四、🔴 「本会话未修改任何生产源码」这句话需要证据链

今晚的报告里写了「**本会话未修改任何生产源码**（三份源文件 mtime 仍为
2026-11-17，无半程落盘）」。这句话**必须能被读者/下一轮会话核验**，
否则就是一句无法证伪的自述。

**证据链（三条，缺一不可）**：

```bash
# ① 三份源文件的 mtime 仍在跑批当天之前
ls -la --time-style=long-iso \
  ~/.hermes/cron/scripts/toutiao-article-daily.py \
  ~/.hermes/cron/scripts/toutiao_topics_extra.py \
  ~/.hermes/cron/scripts/toutiao_story_extensions.py
# → 期望：mtime 是 2026-11-17（上次修改日），不是 2026-11-18（今晚）

# ② 当晚 outbox 产物仍只有 1 个（没有第二份产物 = 没有重跑）
ls ~/.hermes/cron/outbox/toutiao/ | grep -c "$(date +%Y%m%d)"

# ③ history 文件 mtime 未变（没有污染轮换状态）
ls -la --time-style=long-iso \
  ~/.hermes/cron/outbox/toutiao/topic_history.json \
  ~/.hermes/cron/outbox/toutiao/micro_topic_history.json
```

**⚠️ 这三条必须写进报告**，因为下一轮会话要据此判断：
「今晚的源文件是干净的，可以直接开始改」还是「今晚已经改过了，
先读现有源码再决定改什么」。

**反向用例（今晚也真实发生的）**：跨夜碰撞修复的会话里，
「已定位根因 + 已给出方案」被写进了报告，但源码**其实没改**
—— 下一轮会话读到报告以为「已改好」，于是重复劳动或漏修。
**既有纪律「『已定位根因 + 已给出方案』可以写进报告，『已改好』不行」，
今晚再加一条：「未改动」也要附证据链（mtime + 产物数 + history mtime）。**

## 五、通读清单新增第 ⑯ 条链：否定承诺链

| # | 链 | 问什么 |
|---|---|---|
| ⑯ | **否定承诺链** | 标题/钩子断言「某人**没**做某事」，正文里这个人**后来做了**吗？（「一分没出」vs 后文一笔转账） |

**这一链的特别之处**：它是**唯一一个「承诺的兑现方式是缺席」**的链 ——
其余各链都是「承诺的东西要出现」，这一链是「**承诺不存在的东西不能出现**」。

## 六、当晚教训清单（可直接当 checklist 用）

1. **标题里的否定式断言（"没/未/不 + 动作"）是最危险的承诺形态** ——
   现有 `HOOK_PROMISE` 只认「数字要出现」「引语要出现」，
   **否定式承诺完全在覆盖之外**，而读者对「说没出却出了」的反应最强烈。
2. **否定式承诺不要做成硬规则** —— 语义上「出了丧葬费」≠「出了份子钱」，
   正则分不出来；做成硬规则必然假阳性，然后后患是「为了闭嘴改掉对的文案」。
   **定位为通读清单条目 + 扫描脚本粗筛 + 人工核对。**
3. **人物同名/同龄的扫描命中默认是假阳性** —— 对比式提及是双故事论证法的
   标准写法。判别口径：**同名是否出现在该故事自己的动作/结局里**。
4. **年龄撞车不是缺陷** —— 只做提醒，不进通读清单。
5. **扫描脚本分 6 段独立输出**，每段标注命中是「真缺陷」还是「设计约束」，
   不要混在一张清单里。
6. **「本会话未修改生产源码」必须附三条证据**（源文件 mtime / 当日产物数 /
   history mtime）—— 否则下一轮会话无法判断从哪继续。
7. **修复优先级**：读者手上那份已受影响的真缺陷 > 未来夜晚的复读 >
   低价值呼应。**今晚的顺序 = 修 #1（否定承诺，已投递）> #2（钩子复读，
   已投递）> #3（viewpoint 复读）**；低价值呼应（#4/#5）留到有空再做。
