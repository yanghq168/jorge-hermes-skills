# 缺陷八：「钩子承诺不兑现」与「标题党翻车」（2026-11-06 头条号实测）

> 这是 `references/orphan-extensions-and-hand-arithmetic-audit.md`（缺陷六）之后的**第八类内容质量失败模式**，
> 也是 `references/content-self-consistency-checking.md`（缺陷五）之外的**第二类「跨字段失配」**。
> 前两类都是**故事内部**算不通/角色对不上；这一类是**钩子（hook）↔ 正文（story）之间对不上**。

## 一、现象：读者点进来想看的画面，正文根本没写

2026-11-06 头条号那篇《75岁独居老人…》的审计结果**全绿**：

```
audit_rendered_article.py  → ✅ 全部检查通过（正文 3087 中文字，结构 10/10，配图 7 块）
lint_content_consistency.py → ✅ 解析器自检通过 + ✅ 20 条选题未发现数值链/角色/频次矛盾
脚本 exit 0 → HTML 渲染成功 → 飞书附件送达并回查确认
```

但逐段通读抓到：**10 条长文的钩子全部**存在「钩子承诺的具体场景/对话/数字，正文一个字都没有」。

### 实测矩阵（2026-11-06，10/10 命中）

| 方向 | 钩子承诺 | 正文现状 |
|---|---|---|
| 遗产分配 | 三个子女吵了三个小时、差点打起来 | 没写 |
| 赡养义务 | 儿媳在手机上搜「老人养老院一个月多少钱」、她假装没看见 | 没写 |
| 亲戚恩怨 | 侄子发来一条消息，只有四个字：「大伯，我忙」 | 没写 |

| 随礼人情 | 街上遇见当年随过份子钱的邻居，那人**绕道走**，假装没看见 | 没写 |
| 养老院 | **住院那三个月没人陪**；把账算给孩子们听，谁都不说话 | 没写 |

**标题里的引语同样不兑现**（这比钩子更硬 —— 标题是读者唯一的点击依据）：

- 赡养义务标题：第三家说**「住够了」** → 正文无此话
- 亲戚恩怨标题：侄子毕业后第一件事是**「断了联系」** → 正文无此说法

### 为什么这比数字算错更伤

1. **标题党翻车**：头条读者点进来就是为了看钩子承诺的那个画面/那句话，结果正文给的是另一出戏。
2. **「网友投稿」口吻放大了破绽**：钩子用「这是读者@XXX 的投稿」开场，读者会认定故事是真的，
   一对照正文就露馅 → 读者怀疑**整篇都是编的**，包括那些本来写得对的段落。
3. **它 100% 逃过现有所有检查**：`audit_rendered_article.py` 测长度与结构；
   `lint_content_consistency.py` 测算术与角色。**两者都不测「这句话跟这篇文章有没有关系」。**
   这与缺陷五/缺陷六是**同一种盲区**：单字段/单段落自洽，跨字段失配查不到。

## 二、检测口径：只查「可客观验证」的承诺

不要试图用自然语言理解去判断「钩子讲的是不是这个故事」 —— 那不可靠、不可复现。
**只查两类硬承诺**，它们可以用字符串精确断言：

### ① 引号内的对话（最硬）

钩子/标题里用 `'` `"` `「」` `『』` 包裹、且含 ≥2 个汉字的片段，必须在
**装配后的正文**中原样出现。

```python
QUOTE = re.compile(r"'([^']{2,80})'|\"([^\"]{2,80})\"|「([^」]{2,80})」|『([^』]{2,80})』")
```

### ② 具体数字

钩子/标题里出现的阿拉伯数字（年份除外），必须在正文出现。

⚠️ **标题里的年龄也算承诺**：标题写「72岁」而正文只写「62岁」→
读者会以为标题造假。年龄链要在正文里点明一次（本次给遗产分配补「老陈头已经72岁了」、
给亲戚恩怨补「李大爷63岁」）。

### ③ 场景短语（可选，人工层）

「绕道走」「问了他三遍」「假装没看见」这类**动作短语**是叙事钩子，也应兑现 ——
但纯字符串匹配容易因改写而漏报/误报，**建议作为人工通读清单，不作为硬规则**。

### 装配口径：必须测「装配后的正文」

正文 = `story_a` + `story_a_dialogue` + `story_a_ending` + `story_b` + `story_b_ending`
**+ 对应方向的扩写段落**（`toutiao_story_extensions.py` 的 `extra_a` / `extra_b`）。

⚠️ **只测 `story_a` 会误报**：很多兑现段写在扩写里（例如「睡得着觉」在再婚财产的
`extra_a` 里、「手不在你身边」在远居赡养扩写段里）。
⚠️ **只测 `generate_article()` 的返回值也会误判** —— 那是长文 HTML，微头条是后拼的
（见 `references/topic-pool-rotation-and-length-engineering.md` 的装配陷阱）。

## 三、修法：把场景写进正文，**不要把钩子写软**

**错误修法**（把钩子改成正文已经有的内容）：

> 钩子：有一天她看到儿媳在手机上搜「老人养老院一个月多少钱」，她假装没看见。
> → 改成「有一天儿媳对她态度不太好」

这等于砍掉头条最值钱的流量钩子。**钩子是读者点进来的唯一理由，优先级高于正文顺滑。**

**正确修法**（在 `story_a` 前置一段兑现画面）：

> 加一段：大儿媳在厨房刷手机，屏幕上一行字没遮严：王阿姨眼尖，瞥见她在搜
> 「老人养老院一个月多少钱」。她假装没看见，转身回自己屋，把门轻轻带上。
> 那天她心里第一次冒出一个念头：她不是来养老的，是来等一个床位的。

兑现段要**带着新细节**（动作、心理、后果），不能只是把钩子原句复制一遍 ——
否则读者会觉得作者在复读。

### 兑现段放哪里

放在 `story_a` **第一段之后**（人物背景交代完、还没进入主线冲突之前），
或直接作为 `story_a` 的第一段。**不要**塞进 `story_b`（那是另一个人物的故事）。

### 本次落地量

18 处源文件编辑，覆盖 10 条长文 + 1 条微头条，共补写 **25 处兑现片段**。
其中还顺带修掉两处硬伤：

- **错字**：`晚年孤独` viewpoint 里「你**不 定**，他就永远没时间」——
  中间多一个空格，已随 10-18、10-27、11-06 三份产物出厂。
  ⚠️ **中文字符间误插空格**是一个值得全库扫一遍的缺陷类型：
  ```bash
  grep -oP '[\x{4e00}-\x{9fff}] [\x{4e00}-\x{9fff}]' <源文件> | sed 's/.*://' | sort | uniq -c
  ```
  但**要排除合法的 `@昵称 的投稿` 句式**（`@老陈头 的投稿` 是有意的分隔）。
- **微头条内部口径冲突**：老年婚姻钩子写「我想了**三天三夜**」，正文写「想了一晚上」→ 统一为「一晚上」。

## 五、给 linter 新增 `HOOK_PROMISE` 规则的契约

> ✅ **2026-11-07 已落地并实测会 fire**（见下方「2026-11-07 落地结果」一节）。
> 本节保留为设计依据；落地时踩到的坑在那一节。

### 函数签名

```python
def check_hook_promise(hook, title, body):
    """钩子/标题里的引语与数字，必须在装配后的正文出现。

    返回 [(code, msg, ctx), ...]；干净返回 []。
    """
```

- `body` 必须传入**装配后**的正文（扩写已拼进去）。
- 逐条检查 `hook + title` 里的引语片段与数字，命中缺失即报。
- 数字检查要**排除年份**（如 `2026`）。

### 必须接进 `lint()` 主流程

⚠️ **「写了函数」≠「规则生效」** —— 这是 2026-11-05/11-06 连续两晚踩的坑
（`ORPHAN_CHARACTER` 写了却忘了挂进 `lint()`，导致两晚的「全绿」是假的）。
新规则**必须**在 `lint()` 里有一条明确的调用路径，并**用真实反例实测会 fire**
（临时 pool + 临时 extensions 文件，断言退出码 1 且报出 `HOOK_PROMISE`）。
**只跑干净内容 exit 0 证明不了规则接上了**（空集合也 exit 0）。

### 必须配 `_self_test()` 的两条算例

```python
# 正例不报
ok = check_hook_promise(
    "王阿姨说：'我老了，不想拖累你们。'",
    "67岁老人被三个儿子轮流养老",
    "王阿姨说：'我老了，不想拖累你们。'她今年67岁。")
assert not ok

# 反例必报
bad = check_hook_promise(
    "她说：'大伯，我忙。'",
    "63岁大伯给侄子出了20万学费",
    "李大爷63岁，有个侄子叫小强。")
assert bad
```

### 退出码语义不变

`0` = 内容干净 / `1` = 内容有问题 / **`2` = 工具自己坏了**（自检失败）。

### 🔴🔴 落地后立刻暴露规则自身的假阳性 —— 「装配口径」必须按**池型**分叉

第一次跑 linter：**15 处命中**。逐条核对后，**14 处是假阳性**，全部来自**微头条池**。

**根因**：`_hook_promise_body()` 只装配 `story_a` / `story_a_dialogue` / `story_a_ending` /
`story_b` / `story_b_ending` + 扩写。但**微头条池（`MICRO_TOPICS_POOL`）根本没有这些字段** ——
它的正文在 `content` 字段（外加 `micro_dialogue`）。于是微头条的「正文」被装配成空串，
钩子/标题里的每个数字都判定为「未兑现」。

**修法**（已落地）：

```python
def _hook_promise_body(topic, ext):
    def g(k):
        return str(topic.get(k, '') or '')
    # 微头条：正文在 content + micro_dialogue
    if g('content'):
        return '\n'.join(x for x in (g('content'), g('micro_dialogue')) if x)
    # 长文：story_* + 扩写
    body = '\n'.join(x for x in (g('story_a'), g('story_a_dialogue'),
                                  g('story_a_ending'), g('story_b'),
                                  g('story_b_ending')) if x)
    ...
```

修完再跑：**只剩 2 处命中，且都是真缺陷**（微头条「子女不孝」标题承诺「5个电话/4次要钱/1次喝多了」
正文没兑现数字，已改文案兑现）。

### ⚠️ 规则：新增检查器时，**必须对所有池型验证不产生假阳性**

「只跑干净内容 exit 0」和「实测会 fire」这两条**都不够**：
- exit 0 证明不了规则接上了（空集合也 exit 0）；
- 实测会 fire 只证明规则**能**报，不能证明它**不乱报**。

**落地新规则的三步验证（缺一不可）**：
1. **正例不报** —— 干净内容 exit 0；
2. **反例必报** —— 造真反例，断言 exit 1 且报出预期 code；
3. 🆕 **跨池型不误报** —— 对**每一个**选题池跑一遍，逐条核对命中项是否都是真缺陷。
   一个池型一个池型地验（本例：微头条池 vs 长文池字段结构完全不同）。

第 3 步的通用做法：**先用一段脚本把每个池的命中项连同「该池正文字段」一起打出来人工核对**，
而不是只看汇总数。汇总数（15）会让人以为是 15 个缺陷，实际只有 1 个。

### 这次假阳性暴露出的更深一层问题

微头条池与长文池**字段结构完全不同**（`content` vs `story_a`/`story_b`），
而现有 linter 的 `_units_for()` 早就处理了这个分叉。**新增的 `_hook_promise_body()` 却没复用它** ——
自己重写了一套装配逻辑，于是漏掉了分叉。
👉 **新增装配函数前，先看 linter 里有没有现成的池型分叉助手（`_units_for()` / `_ext_pair()`），优先复用。**
自造第二套装配逻辑 = 迟早与主流程漂移。

本例最初只扫 `viewpoint`+`action`，后来扩到 ending 才多抓出 3 处
（养老院 / 远居赡养 / 房产纠纷）。

### ⚠️ 批量改文案时「逐条落盘」（2026-11-07 再次验证）

本轮 20+ 处文案编辑全部用**逐条 assert count==1 → 立即 replace** 的写法，
单条失败即抛异常，避免「全部成功才落盘」把已成功的编辑一起丢弃。

⚠️ **anchor 必须用最小唯一片段**。本轮两次 assert 失败，都是因为照抄记忆里的锚点多了/少了一个字
（`这件事：这20年…` 实际是 `件事：这20年…`；`@老李头 的投稿` 实际无空格）。
**修法：匹配失败时先 `src.find(key)` 打印真实源文本再改，别猜原文。**
